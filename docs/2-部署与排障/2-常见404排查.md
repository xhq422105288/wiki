# 常见 404 排查

> 按顺序查，5 分钟定位。

## 症状 1：整站 404（首页都打不开）

按命中率排序：

1. **Pages Source 选错**：Settings → Pages → Source 必须是 **`GitHub Actions`**。选成 `Deploy from a branch` + 没有 `gh-pages` 分支 = 整站 404。
2. **Actions 还没跑完**：push 后去顶部 Actions 看进度，黄色转圈时等 1-2 分钟，红色失败点进去看日志（多为构建报错）。
3. **地址少了 `/wiki/`**：正确地址是 `https://xhq422105288.github.io/wiki/`，注意结尾斜杠，`/...github.io/` 根路径下是没有这个站的。
4. **刚改过仓库名/可见性**：改名后 Pages 要重新发布一次（随便 push 一个空提交触发）。

## 症状 2：首页能开，点某页 404

- 该页的 `sidebar` 链接和实际文件名对不上（大小写、序号、前缀 `1-` 都要一致）。
- 链接带了 `.md` 后缀，或用了相对路径跳错了目录。统一用 `/分组/文件名` 绝对路径。
- 文件名含空格或特殊符号，改成 `序号-英文.md`。

## 症状 3：本地能看，线上样式全丢

- `config.mts` 里 `base` 和仓库名不一致：仓库叫 `wiki`，`base` 就得是 `'/wiki/'`。
- 改完 `base` 必须重新 push 触发构建，只改本地不发布线上不会变。

## 症状 4：构建失败（Actions 变红）

点进失败的 run，看 `docs:build` 那一步：

- `dead link(s) found`：删掉或修正 aides 指向不存在页面的链接。
- `Cannot find module`：`npm install` 后把 `package-lock.json` 一起提交了没？没提交的话 CI 装的依赖和你本地不一致。

## 还是不行？

带着这三样东西提 Issue，别人才能帮你：

1. 你访问的完整 URL；
2. Actions 失败截图或 run 链接；
3. Settings → Pages 页面的截图。
